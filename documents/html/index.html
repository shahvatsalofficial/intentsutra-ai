    The problem

    Done is easy to claim and hard to prove

    A closed ticket, a merged PR, a test file or a green status is a pointer, not proof. Approvals get attached to text that later changed. Evidence goes stale in silence. IntentSutra makes that visible.

    Stable IDs, explicit unknowns

    Every requirement keeps one ID and a revision number. Missing actor, trigger, authorization and failure paths become questions, never guesses.

    Human approvals, exact revision

    Approval needs a named reviewer, a note, the exact revision and an explicit flag. It is recorded as self-attested, honestly.

    Evidence bound to a version

    Code, test, test-run and release links carry the revision and a SHA-256. Change the requirement and old evidence turns stale.

    Proof, not pointers

    A ticket, a PR or a test file never counts as done. The strongest state is human-attested, never "completed".

    Independent audit, sealed

    Eleven checks recompute hashes and cross-check the registry against the log. JSON, Markdown and HTML, sealed with SHA-256.

    Local, offline, zero dependencies

    No network, no API key, no telemetry. Hostile text stays inert data. The tool never runs your tests or code.

    How it works

    From a rough request to a sealed report

    Every step writes to a hash-chained log. A change at any point creates a new revision and makes earlier approvals and evidence stale.

    1. 1

      Import

      Point it at a brief.

      intentsutra ingest --file brief.md
    2. 2

      Approve and link

      A named human approves an exact revision, then evidence is linked.

      intentsutra approve --confirm-human …
    3. 3

      Audit

      Get a sealed report in three formats.

      intentsutra audit --out audit-out

    One state flow, no "completed"

    What each requirement can be

    The strongest state is human-attested. A revision always sends a requirement back to the start and keeps the old record as stale history.

    FAQ

    Quick answers

    Does it need an API key or internet?

    No. It uses only Node.js built-ins and makes no network calls.

    Does it run my tests?

    No. You import the outcome and it is labelled "not independently verified". A runner is planned.

    Why can a requirement never be "completed"?

    A tool cannot know that. It reports what is observed, imported, attested, stale or missing, and a person decides.

    Is an audit PASS a certification?

    No. It means the recorded evidence is internally consistent. Read the limits section of every report.

    Can someone fake an approval?

    With write access to the files, yes. The audit catches silent edits unless the whole record is rewritten, so keep it in Git with protected branches.

    Can I use it commercially?

    Yes, under Apache-2.0.
